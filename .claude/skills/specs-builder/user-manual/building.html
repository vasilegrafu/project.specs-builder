specs-builder user manual
Part 4: Living with it

Building from it

This page is mainly for developers and for AI that writes code. If you're the business owner, it's enough to know that your specification can answer them directly.

Point an agent at it

An AI agent doesn't need this skill to build from a specification. Each specification's folder holds AGENTS.md, a file agents look for by themselves, and it tells them what to read, what to ask and what never to touch. app/guide/ holds the rest: build.md, the procedure step by step; query.md, every command; model.md, the form of the data.

An agent that starts in the folder finds all of this. One that starts in the code project doesn't, so tell it where to look:

The product specification is in ../specs: read ../specs/AGENTS.md before building from it.

Put that line in the code project's own AGENTS.md or CLAUDE.md, and every agent that works there gets it. The agent needs Python 3.14 or later to ask its questions, and nothing else.

The commands

Step Command
See what is here python app/spec.py overview
Plan the work as user stories python app/spec.py story
Get the order to build in python app/spec.py plan
Get all one thing needs python app/spec.py unit R4
Get its tests python app/spec.py tests R4 --gherkin
Check it may be built from python app/spec.py verify
Record what the code is built from python app/spec.py snapshot --target ../code
See what moved since, and what to redo python app/spec.py changed --target ../code
See what the code carries python app/spec.py coverage

plan divides the work into slices, each ending in something that runs: first the foundation everything stands on, then what no flow passes, then one slice for each flow. unit, tests and open take a slice, as in unit F1, or any single thing.

One unit, with everything it needs

Its tests

Every test names the criterion it proves. Write R4.2 or R4_2 in the test's name or a comment beside it. Scenarios from tests --gherkin already do. Those names are the only tie between the code and the specification, and coverage reads them. It exits 1 while a criterion of a must or a should has no test. It reads names only, so it cannot tell you that a test passes.

Ask back. Never guess, and never edit. Where the specification does not settle what you are building:

python app/spec.py ask "Does the limit of five count other devices?" --about R4 --by "the builder"

The question waits in inbox.md, outside the data, and appears first under What is open. Whoever keeps the specification makes it an open question, or answers it and closes it. ready holds while any waits. Build what does not depend on the answer meanwhile.

What else it answers

Each of these takes --json for a program. app/guide/query.md in the folder says every one with its options.

Ask To learn
look SC3 How a screen or a component looks: each element and how to find it in the prototype
outline SC3 The prototype as a tree. --state empty or --as signed-in shows only what appears then
words SC3 Every word on the screen, to use as it is
forms SC3 Each field, its label, its rules and its options
links SC3 Where each element leads, and what leads here
states SC3 What each state and variant changes, and the widths the layout changes at
styles SC3.13 The colours, sizes and fonts an element is drawn with
tokens The colours, sizes and fonts as one list, and as CSS
sample The sample data the prototypes show
messages Every message the product shows, its errors included
schema N1 An entity as JSON Schema
lifecycle N1 The states an entity moves through
permissions Who may do what, as one table
rules Every rule, and what makes it true
glossary The product's words, to use in the code
qualities How fast, how accessible, and what is fixed from outside
openapi The API's description
list requirement Every node of a kind; list kinds gives the kinds
find delivery Every node that says the words
edges B1 Every link to and from a node
export --model The whole specification as JSON files, for a program

When the specification moves on

snapshot --target ../code records what the code was built from. After a change like five becoming six, changed --target ../code says what moved, down to a word on a screen, a colour or a sample price, and what to redo. In the application, What is built shows what the code carries.
