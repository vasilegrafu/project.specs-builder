The operator on call, with a mail that says the night failed, ends with the shop's stock in line with the feed, or with the supplier called.

## Diagram

```mermaid
flowchart TD
    start(["The morning mail says FAILED"]) --> why{"What does it say?"}
    why -->|"could not be fetched"| wait["Wait until after 08:00"]
    wait --> rerun["Run the job by hand"]
    why -->|"stale"| call(["Call the supplier's desk; no rerun with the old feed"])
    why -->|"out of shape"| keep(["Keep the feed as a file for the developer; nothing is written"])
    why -->|"a write refused"| up["Wait for the catalogue to be up"]
    up --> rerun
    why -->|"held off"| running{"Is a run still going?"}
    running -->|"no"| remove["Remove the lock left behind"]
    remove --> rerun
    running -->|"yes"| leave(["Leave it to end"])
    rerun --> again{"How does it end?"}
    again -->|"done or nothing to do"| fine(["The shop's stock matches the feed"])
    again -->|"still 503"| call
```

## Steps

1. The operator reads the morning mail, which says FAILED and why, and opens the runbook at that outcome. R6
2. Where the feed could not be fetched, the supplier's rebuild ran late: the operator waits until after 08:00 and runs the job by hand. A1, R2
3. Where the feed was stale, the operator calls the supplier's desk and does not rerun with the old feed; a feed file of the old one would be refused all the same. A3, R9, R3
4. Where the feed was out of shape, the operator keeps the feed as a file for the developer; nothing is written until the job reads the new form. A3, R9
5. Where a write was refused, the operator waits for the catalogue and runs the job by hand; the rerun writes only what still differs. A1, R5
6. Where the run was held off and no run is going, the operator removes the lock left behind and runs the job by hand. A1, R7
7. The rerun ends done or with nothing to do, and its outcome is in the day's log; where the supplier still answers 503, the operator calls its desk. A1, R10
8. The operator calls the supplier's desk by phone, outside the job.

## When it goes wrong

| What fails | Then | Seen by | Stands on |
|---|---|---|---|
| the supplier still answers 503 after 08:00 | the rerun is refused with exit 2, R2 | the operator, on the command's exit code and in the log; the supplier's desk is called | R2 |
| the catalogue still refuses the same SKU | the rerun stops with exit 3, the writes before it kept, R5 | the operator, by the exit code and the mail naming the SKU | R5 |
| the operator removes a lock while a run is still going | two runs write at once, which the lock is there to prevent, R7 | nobody, until two lines of the log disagree: the runbook says to look for the process first | R7 |
| a feed file the operator gives is stale or out of shape | refused as the fetched feed would be, R9 | the operator, on the exit code and the reason | R9 |
