# Files and media

- **What it is:** Anything users upload or the product produces as a file. It covers documents, images, attachments, their size and type limits, and who can open them.
- **Applies when:** Users attach, upload or download files, or the product shows images they provide. A product that deals only in entered text and numbers can skip it.
- **If left unsaid:** Any file of any size is accepted, stored forever and served to whoever has the link. The limits arrive later as outages and a storage bill.
- **Ask:**
  1. What will people upload, and why -- as evidence, to share, to be processed?
  2. How big is a typical one and the largest reasonable one? How many per user?
  3. Does the product need to look inside the file, or only keep it?
  4. Who may open a file once it is uploaded?
  5. How long must it be kept, and may the uploader remove it?
- **Options:**
  - no files, a link instead -- users paste a link to where the file already lives; nothing to store or secure, and the link breaks when they reorganise.
  - attachments as they are -- store and return the file unchanged; simple, with limits on size and type.
  - files the product displays -- previews, thumbnails, images shown in pages; much friendlier, and each file type is work.
  - files the product reads -- extracting data from spreadsheets or documents; valuable and unpredictable, since real files are never as expected.
- **First release:** Attachments stored and returned unchanged, with a stated size limit and a short list of allowed types, visible only to those who can see the thing they are attached to. Previews and reading inside files wait.
- **Often forgotten:** A file that is too large, the wrong type, or interrupted half way. Photographs from phones, which are large and may be sideways. A file with the same name uploaded twice. Files that carry a virus or personal data. What happens to files when their owner or their record is deleted. Download links that still work after access is removed.
- **Becomes:** Requirements for uploading and opening with the refused cases; capacity and security quality requirements, with numbers; a privacy constraint on retention; an open question for engineering on storage cost; non-goals for preview and extraction.
